- World key rendering (do not regress): the keyboard's atlases are NOT used for it (tuned for ~60px keys over a black void; failed at poster size). It is ray traced live: the Blender keycap with a flat, level face (`scripts/render-world-key.py` exports `public/models/world-key/keycap.glb`; dish filled, rings kept so face normals stay flat) is the surface; inside, light is traced through the same generator profile (13 rings → Hermite → 1024-sample half-float lookup, analytic normals, bracketed exit solve; the key is convex) with total internal reflection, absorption and per-IOR exits (1.47/1.535/1.62), thin-film entry Fresnel, Blender AgX LUT. Studio = the Cycles one (`src/lib/world-key-studio.ts`, verified against Blender: card axes, pose, Generated = direction): a light tent (paper, soft grey on the camera side), black flags, travelling softboxes; behind the key the ray meets the poster page (paper + the statement drawn from the DOM at its layout), so the type refracts through every face. The key's resting tilt is shallow (≈0.44 rad) so the page is seen through the front wall too. Budget: ~2–4 ms GPU on M1 Pro desktop at ~1.5×, ~2 ms phone at 2× (pixel budget 1400 px wide, adaptive below). Cycles still (`npm run assets:world-key`) is the no-JS/no-WebGL image and the reference for live (`docs/qa/world-key/cycles-vs-live.png`).
- World key physics (`src/lib/key-physics.ts`): rigid body on a suspension (force at the touched point → torque) plus soft-jelly modal dynamics (squash with volume-keeping bulge, two sways, twist, dent at the touch); each mode excited by φ(c)·F at the contact, so where you press changes the response; ζω≈2.9/s so it settles in ~1 s; a held press creeps deeper (mochi); a tug is limited to ~0.14 units. Same shape functions deform the mesh in the vertex shader. Reduced motion: critically damped, still lights.

- (Paused) Navigation direction (2026-11-06; plan in `docs/world-redesign-plan.md`, look in `docs/qa/display-study`): there is no web chrome at all (no header, menu, hamburger, footer links, close buttons, breadcrumbs or cards). Visible text is only light: in the hero, typed words, predictions, the ⌘ map and signatures float in the void; in a world, the page is light inside an ice display. Both are painted from an invisible HTML twin that stays the real, accessible, indexable document (links, fields, focus and scrolling are live). On Enter the keys clear away (each on its own path) and a curved display of the same crystal freezes into being from its edges; only the ESC key stays, beside the display's lower-left corner, as the way home. Pages need no keyboard: letters do nothing there; 1–3 select works, ←/→ move between works, Backspace un-types the world to its parent, Escape leaves (inside a field it only blurs and keeps the draft) and the keys return. The Studio99 logo key (F-row right, the only non-standard legend) is in the hero keyboard. Unknown words get their own URL and carry into CONTACT. Without WebGL or scripting, the twin is shown as plain readable text.
- The ice display always faces the camera around the twin's CSS frame (`.display-frame`), so its optical look is a Cycles bake per shape (`scripts/bake-ice-display.py` → `public/models/ice/{landscape,portrait}.png`); the browser adds the page light and the freezing. Re-bake when the frame proportions in CSS change; the canonical frames are listed in the script.
- Preserve clear black glass and bright white edges. Revision 4 optics samples Blender's linear radiance bases by actual light/key/view directions, with RGBM16 and Blender AgX. Never reintroduce per-key time/hue cycling. Seven fixed reflection cards exclude the two moving emitters; white area lights travel unevenly, and live thin-film Fresnel adds angle-dependent surface iridescence. This remains a fixed-camera transport approximation. Hover only excites a spring (no held enlargement, brightening or lift). Presses use firm compression and a longer torsional tail; retain taps between render frames. Inside a world, render on demand (still while reading; frames only for scroll, input and transitions); pause when hidden.
