# STUDIO99 — TYPE YOUR WORLD.
## Creative Direction & Engineering Specification

あなたは、世界最高水準のCreative Technologist、Art Director、UX Designer、3D Technical Artist、Frontend Engineerです。

Studio99合同会社の新しいコーポレートWebサイトを、実際に動作するプロダクション品質で制作してください。

今回は仕様を提案するだけではありません。既存リポジトリを調査し、Blenderアセット制作からNext.js実装、アニメーション、テスト、ビジュアル検証まで実行してください。

最重要なのは**添付された承認済みHero画像の再現性**です。独自のアートディレクションで置き換えてはいけません。

---

# 01. CENTRAL CONCEPT

**TYPE YOUR WORLD.**

入力によって、目の前の世界が変わる。

Studio99のWebサイトは、浮遊する3Dキーボードそのものがインターフェースである。

訪問者が言葉を入力すると、それに対応するコンテンツ、作品、あるいはまだ存在しない世界が現れる。

通常のWebサイトのようにメニューを探してクリックするのではなく、訪問者が自ら言葉を入力し、意味を成立させ、世界を呼び出す。

この体験自体をStudio99のクリエイティビティの証明とする。

# 02. ART DIRECTION — ABSOLUTE PRIORITY

添付画像をビジュアルの正本とする。

### 絶対に保持する表現

- 完全な黒に近い背景
- 空間に浮遊するフルサイズのキーボード
- キーボード筐体は存在しない
- すべてのキーキャップが独立している
- 整然としたキーボード配列
- 斜め上からの立体的なカメラアングル
- ダークガラス／クリスタル状のキーキャップ
- ガラスの内部やエッジに現れる虹彩的な屈折
- 紫、青、シアン、橙、マゼンタの微細な分光
- 極めて高いコントラスト
- 前景・背景の部分的な被写界深度
- 余白が支配するミニマルな構図

重要：虹色は発光するネオン照明ではない。透明体への光の入射・反射・屈折によって現れる光学的な色彩として扱う。

全体をカラフルにしてはならない。

### 禁止する表現

- 白いキーボード
- ゲーミングRGBキーボード
- 普通のプラスチック製キーボード
- キーボードの筐体
- 不自然なキーの散乱
- 大きなカード型UI
- 不必要なグラデーション背景
- 巨大なキャッチコピー
- 常時激しく動くパーティクル
- 典型的なSaaSランディングページ

### Composition

デスクトップの基準画角は1440×900。

上部左端：Studio99®

上部右端：TOKYO / NAGANO

画面中央：浮遊する完全なキーボード

中央上部：入力文字列、または TYPE TO EXPLORE

下部左：CREATIVE CAPITAL COMPANY

画像と同等の余白、奥行き、カメラ位置を保つ。

# 03. KEYBOARD OBJECT

US QWERTY配列を採用。

Functionキー、数字キー、アルファベット、記号、修飾キー、Space、Enter、Backspace、矢印キーを含む。

基本的なキー配列は承認済み画像に一致させる。テンキーの追加など、画像の構図を変える改変は行わない。

各キーは独立したインタラクティブな3Dオブジェクト。

すべてのキーは通常のキーボード同様の文字や記号を持つ。ABOUTやWORKSなどの単語をキーキャップ自体に刻印してはいけない。

### Interaction

物理キーボードとマウス操作を統合する。

- 物理キー押下 → 対応する3Dキーが沈む
- 物理キー解放 → 3Dキーが元の位置に戻る
- 3Dキーをクリック → 同じ押下アニメーションと入力処理
- 3Dキーをタッチ → 同様に反応
- 同時押下 → すべての該当キーがそれぞれ反応
- Hover → ガラス内部の反射が微細に変化

押下は80〜120ms程度を起点に調整する。

単なるY座標の変更ではなく、スイッチが沈み込む物理的な気持ちよさを設計する。

平常時のキーボードはほぼ静止させる。

# 04. COMMAND LANGUAGE

コマンドは設定データとして一元管理する。

初期コマンド：

| Input | Action |
|---|---|
| ABOUT | Studio99の企業情報を開く |
| WORKS | Works一覧を開く |
| CONTACT | 問い合わせ画面を開く |
| RUBICON | Rubiconの作品ページ |
| BI | Beauty Instituteの作品ページ |
| ON | ONの作品ページ |
| ESC | 現在の画面を閉じてHeroへ |
| BACKSPACE | 最後の文字を削除 |
| ENTER | 現在の文字列を確定 |
| ⌘ / CTRL | コマンドヒントを表示 |

公開対象の作品情報は既存リポジトリにある実データを優先する。存在しないケーススタディや実績情報を捏造しないこと。

未知のコマンドを任意に追加できる設計とする。

### Activation rules

- 入力文字列は大文字・小文字を区別せず照合する。
- ABOUTなど長い既知コマンドは、完全一致後、短い入力停止時間を経て自動起動する。
- ENTERで即座に確定できる。
- BI、ONのような2文字コマンドは誤起動を防ぐため、ENTER確定を基本とする。
- 未知の文字列は、途中入力では発火せず、ENTERで確定する。
- 文字入力再開時には保留中の自動実行をキャンセルする。

# 05. PREDICTIVE WORLDS

**ここは主要なクリエイティブ機能である。**

利用者の入力途中で、存在するコマンドの候補が徐々に現れる。

例：

ユーザーが `A` と入力する。

画面上に以下がごく薄く出現する。

ABOUT — WHO WE ARE

続けて `B` を入力すると、ABOUTの文字がさらに明瞭になる。

`ABO` まで進むと、残りの `UT` がGhost Textとして提示される。

ABOUTが完成すると、その世界が開く。

### Requirements

- Prefix Matchingによるコマンド候補検索
- 候補への徐々に強まる視覚的フィードバック
- 補完文字は入力済み文字より薄く表示
- 候補をマウスで選択することも可能
- 候補へのHoverで、対応する3Dキーが順番にごく弱く反応
- BACKSPACEで候補も自然に巻き戻る
- 未知の入力で候補がゼロになってもエラーを出さない

候補表示は巨大な検索結果パネルではなく、キーボード上空に現れる静かなタイポグラフィとして表現する。

# 06. COMMAND KEY — KNOWN WORLDS

⌘キーを押している間、主要なコマンドの一覧を表示。

クリック／タップした場合は固定表示の切り替えとする。

Windows/LinuxではCtrlにも対応し、`?` と画面上のヘルプ操作でも表示できるようにする。

既存のブラウザショートカットを妨害してはいけない。

表示：

KNOWN WORLDS

ABOUT — WHO WE ARE

WORKS — WHAT WE CREATE

CONTACT — MAKE ONE WITH US

OR TYPE SOMETHING THAT DOESN'T EXIST.

ヒント内のコマンドにHoverすると、対応するキーが順番に弱く光る。

ただし、非公開の隠しコマンドまで全表示しない。

# 07. UNKNOWN WORLDS

**このサイトの重要なブランド体験。**

既知のコマンド以外の言葉を入力し、ENTERを押すと、未知の世界が出現する。

例：MOON

表示：

UNKNOWN WORLD

MOON_

THIS WORLD DOESN'T EXIST. YET.

MAKE IT WITH US.

最後の一文はCONTACTへのCTA。

### Visual behavior

未知のコマンドが確定すると、

1. キーボードがわずかに奥へ移動する
2. 入力された言葉が空間に残る
3. UNKNOWN WORLDが静かに出現する
4. メッセージが表示される
5. CTAが操作可能になる

過剰な爆発、発光、派手なページ遷移は禁止。

未知の単語の入力自体を否定的に扱わない。

この状態からESCで元のキーボードに戻れること。

# 08. SPECIAL KEY INTERACTIONS

### SPACE

入力欄が空のとき、Spaceを長押しすると各キーの間隔が徐々に広がる。

離すと元の配列へ帰還する。

通常の文字入力中は空白入力を優先し、演出と衝突させない。

### SHIFT

Shiftを押している間、キーキャップのガラスにごく微細な内部構造やワイヤーフレームを重ねる。

ただし、通常のShift入力を阻害しない。

### ESC

コンテンツ表示、入力文字列、開いたヒントなどの状態を適切に解除する。

Heroに戻るとき、3Dキーは元の配置に復元される。

### 99

将来的なHidden Experience用に予約する。

初期実装では未使用でもよい。

# 09. CONTENT TRANSITION

既知のコマンドが成立した際、完全なページリロードを発生させない。

キーボードは背景の奥へ移動し、対応するHTMLコンテンツを前景に表示する。

About、Works、Contact、各Works詳細には個別URLを設ける。

直接URLへアクセスでき、ブラウザの戻る操作でも状態が破綻しないこと。

SEO対応のため、主要コンテンツは検索エンジンから参照可能なHTMLとして提供する。

3Dを読み込めなくても、企業情報と作品情報にアクセスできること。

# 10. BLENDER PRODUCTION PIPELINE

Blender Python APIを利用して、キーキャップの3Dモデルを再現可能なスクリプトで自動生成する。

### Geometry

- 1uキーキャップを基準にする
- Wide key用のサイズバリエーション
- Spacebar用の専用形状
- 傾斜する側面
- 精密なベベル
- 厚みのある透明体
- 上面の微細な曲面
- 独立したキーごとのTransform

一般的な角丸Boxを並べるだけの実装は禁止。

### Material

目標は承認済み画像の黒い虹彩ガラス。

Transmission、IOR、Roughness、Iridescence、Fresnel、環境反射を適切に利用する。

BlenderのCyclesレンダリングとWebGL上の材質は必ずしも一致しないため、GLBを書き出すだけで完成と判断してはいけない。

ブラウザでの最終表示を基準に調整する。

### Asset workflow

1. キーキャップの基本形状をBlenderで生成
2. ガラス材質とライティングを検証
3. サイズバリエーションを制作
4. GLB形式で出力
5. Three.js側でキーボード配列に配置
6. 文字ラベルを高解像度かつ効率的に実装
7. WebGL上で画像と比較
8. 違いがあれば調整

元となる.blend、生成スクリプト、Web用GLBを保存する。

100個以上のキーを1個ずつ独立制作するのではなく、再利用可能な形状とマテリアルを活用する。

各キーの入力判定とアニメーションは独立させる。

# 11. TECHNICAL ARCHITECTURE

技術構成：

- Next.js App Router
- TypeScript
- React Three Fiber
- Three.js
- Drei
- Blender Python API
- 必要に応じてGSAP
- PlaywrightによるE2Eテスト

まず既存リポジトリの技術構成を調査し、互換性のある安定版を使用する。

入力・描画・コマンド解決・ページ遷移を分離する。

推奨モジュール：

- `KeyboardScene` — 3D空間の描画
- `Keycap` — 3Dキーの再利用可能な表現
- `KeyboardLayout` — キー配列データ
- `KeyboardInputController` — 物理入力とポインタ入力の統合
- `CommandRegistry` — コマンド定義
- `CommandResolver` — 入力照合と補完
- `WorldTransition` — 状態遷移と演出
- `CommandHints` — コマンド表示
- `UnknownWorld` — 未知の世界
- `ContentOverlay` — 各ページ表示

実際の命名や配置は既存リポジトリに合わせて最適化してよい。

### Critical keyboard handling

`KeyboardEvent.code` を物理キーの3D位置への対応に利用する。

入力文字そのものの解釈には `KeyboardEvent.key` 等を適切に利用し、物理キー位置と文字を混同しない。

日本語IMEの変換中、フォーム入力中、ブラウザショートカット操作中は、グローバルなコマンド入力を誤発火させない。

`keydown` / `keyup` / `blur` の状態管理を実装し、押されたキーが沈んだままになる不具合を防ぐ。

マウスと物理キーボードは単一の入力状態機械に接続する。

# 12. PERFORMANCE & ACCESSIBILITY

### Performance

デスクトップで滑らかな60fpsを目標とする。

ガラスのTransmissionは高負荷のため、全キーが独立した高コストの屈折レンダリングを行うような構成は避ける。

- Geometry共有
- 必要に応じたInstancedMesh
- マテリアル・テクスチャ共有
- 描画負荷の計測
- デバイス性能に応じた品質調整
- 不必要な再レンダリングの抑制
- 遅延ロード

を実装する。

### Accessibility

- キーボード操作対応
- フォーカス表示
- スクリーンリーダー向けのHTMLナビゲーション
- prefers-reduced-motion対応
- WebGL非対応時のフォールバック
- モバイルでのテキスト入力手段

3D表現を体験できない人も、Studio99の情報にアクセスできる状態を保証する。

スマートフォンでは既存Heroのビジュアルを可能な限り保持しつつ、必要に応じてテキスト入力UIを併設する。

# 13. QA & ACCEPTANCE CRITERIA

完成条件：

1. 添付画像と構図・質感・光の方向性が一致している
2. キーボード全体が表示されている
3. すべての必要なキーが個別に反応する
4. 物理キーボードと3Dキーが同期する
5. ABOUTの途中入力で候補が現れる
6. ABOUTの完成で該当コンテンツが開く
7. ⌘キーで主要コマンド一覧が現れる
8. MOONなど未知の単語でUNKNOWN WORLDが現れる
9. MAKE IT WITH USからContactへ移動できる
10. ESCでHeroへ戻れる
11. URL直アクセス、戻る操作が機能する
12. モバイル、WebGL非対応環境でも主要情報を利用できる
13. ビルド・型チェック・主要な自動テストが通る

ビジュアル品質の評価は、機能テストとは独立して行う。

ブラウザ画面のスクリーンショットを撮影し、承認済み画像と並べて検証すること。

以下は未完成と判断する：

- キーボードがただの四角いBoxの集合
- ガラスの造形と光学表現が不足
- 入力はできるが3Dキーが連動しない
- コマンド補完が機能しない
- 参考画像から著しく離れたグラフィック
- 未知の世界が単なる404ページ
