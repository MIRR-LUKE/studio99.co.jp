## 1. 目的

一般的なWebサイトの部品と慣習を、画面から一つ残らず消す。訪問者は、浮遊するガラスのキーボードと、その背後に灯る光だけで、会社・作品・問い合わせにたどり着く。同時に、キーの氷のような透明感と虹彩を、写真と見分けがつかない水準に近づける。

## 2. 世界のルール

1. **素材は2つだけ**：ガラス（キー）と光（背後の湾曲スクリーンに映る光）。
2. **画面に出る文字は、キーの刻印か、スクリーンに映った光だけ**。HTMLの文字やWebの部品は見せない。例外は、3Dを表示できない環境向けの文字だけの版のみ。
3. **操作はキーの意味だけで行う**。誰もが既に知っている意味（打つ、確定、抜ける、消す、番号で選ぶ、隣へ）を使い、説明もメニューも置かない。
4. **単語をキーに刻印しない**。唯一の例外が Studio99 のロゴキー（ユーザー発案）。
5. **HTMLは「見えない双子」として常に存在する**。検索エンジン、読み上げソフト、キーボード操作、3D不可の環境は、この双子を使う（§6）。
6. **黒は黒**。虹は発光ではなく光学現象。ネオン、RGB発光、パーティクル、グリッチ、走査線、CRT風の演出は使わない。

## 3. 舞台

### 3.1 湾曲スクリーン
| 項目 | 内容 |
|---|---|
| 形 | キーボードの背後で画面全体を覆う、水平方向に湾曲した円筒の一部。枠・縁・台はない。消えているときは闇と区別できない |
| 映り方 | 中心が最も明るく鋭く、端ほど暗く柔らかい。明るい文字にだけ微かなにじみ。黒は持ち上げない（プロジェクターの黒浮きなし） |
| 湾曲の見せ方 | 端に置いた小さな文字（TOKYO / NAGANO、CREATIVE CAPITAL COMPANY、PREVIEW）が曲面に沿って曲がることで、スクリーンの存在が伝わる |
| Hero での状態 | 消えている。点滅するカーソルと、打った文字だけが映る |
| 文字の描き方 | Canvas 2D で高解像度のテクスチャ（デスクトップは幅4096px目安）に描き、曲面に貼る。日本語と既存の書体がそのまま使える。内容が変わったときとスクロールしたときだけ描き直す |
| 検証で決める値 | 半径、弧の角度、キーボードからの距離、テクスチャ解像度、端の減光量 |

### 3.2 キーボード
- Hero の姿勢と漂いは現状維持。
- 世界の中では、画面の高さの5〜8%だけ下がり、わずかに小さくなる（値は検証で決める）。漂いの振れ幅を抑える。
- **ピント送り**：読んでいる間はピントがスクリーンにあり、キーは少しボケる。打ち始めるとピントがキーに戻る。被写界深度は今は実装されていないので新規に作る。
- **キーの3つの状態**
  - 通常
  - 押されたまま：今いる世界の言葉の文字。現在地を補う
  - 立ち上がる：その場で役割のあるキー。押せることを示す
- **ロゴキー**：F列の右端（Macの電源ボタンの位置）に置く1uのキー。刻印は Studio99。世界の中で押すと Hero へ戻り、Hero で押すと自己紹介の実演（§5）が始まる。99 の隠し体験の入口候補として予約する。

### 3.3 キーがスクリーンを屈折する
すべてのキーは、背後のスクリーンの光を波長ごとに屈折させて見せる。明るい言葉がキーの後ろを通ると、ガラス越しに曲がり、虹色ににじむ。作り方は §7.1。

## 4. 操作の文法

| キー | Hero | 世界の中（入力欄の外） | 入力欄の中 |
|---|---|---|---|
| 文字・数字 | 打つ（スクリーンに映る、予測の続きは薄く） | 打つ。そのままの状態で別の世界へ行ける | 普通に入力。手前のキーも沈む（見た目だけ） |
| RETURN | 確定 → 世界が灯る | 確定。WORKS で選択中なら開く | フォームの既定の動作 |
| ESC | 入力を消す。点灯中なら取り消す | スクリーンが消え、Hero に戻る | フォーカスを外すだけ（下書きは残す） |
| BACKSPACE | 1文字消す | 打ちかけの文字があれば1文字消す。なければ、押されたままのキーを後ろから1つずつ戻し、見出しも1文字ずつ消える。消し切ると一つ上へ（RUBICON → WORKS → Hero） | 普通に削除 |
| ⌘ / Ctrl を押している間 | 地図（§5） | 地図 | ブラウザのショートカットを優先 |
| SHIFT を押している間 | 構造線が見える（現行） | 同じ | 普通に入力 |
| SPACE | 何も打っていなければ長押しでキーの間隔が広がる（現行） | スクロール | 普通に入力 |
| 1・2・3 | 打つ | WORKS で何も打っていなければ、その作品を選ぶ（Enter で開く） | 普通に入力 |
| ← → | なし | 作品詳細で何も打っていなければ、隣の作品へ（循環する） | カーソルの移動 |
| ↑ ↓、PageUp/Down、Home/End | なし | スクロール | 既定の動作 |
| TAB | 見えない双子の中でフォーカスを移す。フォーカス先はスクリーン上で白く強調され、対応するキーが立ち上がる | 同じ | 既定の動作 |
| ロゴキー | 自己紹介の実演 | Hero へ | — |
| F1〜F12、⌘/Ctrl＋文字 | 横取りしない（キーが沈む見た目だけ） | 同じ | 同じ |

- 日本語の変換中、⌘・Ctrl・Alt との同時押しは、コマンドとして扱わない（現行の保護を維持）。
- 物理キー、3Dキーのクリック、自動の打鍵（実演や地図からの選択）は、すべて `src/lib/input-machine.ts` の同じ reducer に、入力元だけを変えて送る。
- URL が常に正。世界の状態は pathname から組み立てる。

| マウスを乗せる | キーが小さく弾む（現行）。そのキーの文字で始まる世界が、スクリーンにごく淡く映る |
| ⌘ の地図 | キーボード上で、ABOUT・WORKS・CONTACT の文字を打つ順に結んだ細い白線が同時に描かれる。線は漂うキーに付いていく。スクリーンには3つの言葉と短い説明が映る。言葉にマウスを乗せると、その線が明るくなりキーが順に沈みかける。クリックすると、キーが実際にその言葉を打って Enter まで押す |

| 読む | キーボードがわずかに下がり、ピントがスクリーンへ移る。スクロールすると、行がキーの裏を通る間だけガラス越しに曲がって見える。静止中は描画しない |
| 世界から世界へ | そのまま文字を打つと、スクリーン下部に入力中の文字が映る。Enter で本文が消え、新しい言葉が巨大に映る。Hero には戻らない |
| WORKS | 3作品が番号つきで映る。手前では 1・2・3 のキーが立ち上がる。番号のキーか作品名の入力で選び、Enter で開く |
| 作品詳細 | ← → が立ち上がる。隣の作品へ移るとき、作品名のキーが入れ替わる |

| UNKNOWN WORLD | スクリーンは言葉と「THIS WORLD DOESN'T EXIST. YET.」だけを灯し、それ以外は暗いまま。RETURN が立ち上がり、押すと CONTACT が開いて、問い合わせ本文にその言葉が入っている |

| ブラウザの戻る | URL から状態を組み立て直す。前の世界への切り替えは短い入れ替えだけにする |

## 6. 見えない双子（アクセシビリティ・SEO）

- 各 URL は今と同じく静的 HTML（見出し、本文、リンク、フォーム）を出力する。検索エンジンと読み上げソフトはこれを読む。
- 画面上では視覚的に隠す。スクリーンに映す内容は、この双子から生成する（文言を二重に管理しない）。
- **スクロール**：双子と同じ高さの見えないスクロール容器を全画面に置き、そのスクロール量で映像を動かす。慣性スクロール、キーボードでのスクロール、タッチ操作がブラウザの標準のまま使える。
- **フォーカス**：Tab は双子のリンクと入力欄を移動する。フォーカス中の項目は、スクリーン上の白い強調と、キーの立ち上がりで示す（世界の中のフォーカス表示）。
- **入力欄**：スクリーンに映った欄をクリックすると、双子の入力欄にフォーカスが移る。
- **3D不可・JavaScript なし**：双子をそのまま表示する（黒地、同じ書体）。これが唯一の文字だけの版。
- **諦めるもの（明記する）**：スクリーン上の文字の選択とコピー、ブラウザの翻訳表示、ページ内検索の強調、ブラウザ拡大での折り返し。これらが必要な人は、双子（3D不可の版と同じもの）を使う。双子への切り替えは、フォーカス時にだけ現れる入口で行う。

## 8. 性能と容量の予算

- 現状（`docs/qa/verification.md`）：1440×900 で平均60.11fps、通常時151 draw calls、光学データのダウンロード8.39MiB、アトラスのGPUメモリ約94MiB（デスクトップ、M1 Pro）。
- 予算案（目安、§10で確認）：
  - フレーム：平均55fps以上、95%点20ms以下（1440×900、同じ環境）
  - ダウンロードの追加：6MiB以内
  - GPUメモリの追加：64MiB以内
- 描画：読んでいる間の静止中は描画しない。スクロール、ピント送り、入力、点灯の間だけ描く。タブが非表示のときは止める（現行）。
- スクリーンの屈折用に、半分の解像度の描画先を1枚追加する。
- スマホ：描画解像度の上限を下げ、スクリーンのテクスチャも小さくする。実機での計測を行う（今は未実施）。

## 10. 承認が必要な項目（今の指示・仕様の変更）

1. 「コンテンツが開く前にキーが散開する」をやめる。キーはほぼその場に残り、背後のスクリーンが灯る（AGENTS.md の最新の動きの指示）。
2. 「コンテンツ表示中は連続描画を止める」を、「静止中は描画せず、操作中だけ描く」にする。読んでいる間は反射の動きも止まる。
3. 世界の中で打った文字をコマンドとして受け付ける（今は見た目だけ）。
4. Backspace で一つ上の世界へ戻れるようにする。
5. ナビの部品と、画面上のHTMLの文字をすべて撤去する（仕様書02の構図の要素は、世界の中へ移す）。
6. ロゴキーを置く（仕様書03「通常の文字のみ」の例外）。
7. 未知の URL では UNKNOWN WORLD を表示する。
8. 仕様書07「キーボードがわずかに奥へ移動する」を、スクリーンを使う形に置き換える。
9. §8 の性能・容量の予算。

承認後、AGENTS.md の最新の指示と仕様書を、この計画に合わせて書き換える。

## 11. Claude の推奨する決定

- スクリーンの文字は Canvas 2D で描く。理由は、日本語、既存の書体、描画の自由度。
- 世界の中では、いつでも打てるようにする。入力欄、日本語の変換中、修飾キーとの同時押し、スクロール用のキーは除く。
- 作品の前後移動は循環させる（ON の次は RUBICON）。
- キーごとの個別の光学計算はしない（§7.9）。
- 実装の順番は、P1 の光学の検証を先にする。見た目が決まらないまま操作を作ると、作り直しが大きくなるため。P0 は独立しているので、すぐに直してよい。

## 12. リスク（重い順）と、それを確かめる方法

1. **ブラウザでの屈折が Cycles の正解に届かない** → P1 で並べた画像で判断する。届かない場合は、地図の波長数と解像度を上げる。
2. **曲面に映る文字が読みにくい**（湾曲、にじみ、ピント送り） → P3 で About 全文を両方の画面幅で確認する。
3. **説明の文字がないと、初めての人が迷う** → P8 の3人の観察。10秒以内に打ち始めるかを見る。迷う場合は、実演の開始を早め、マウスを乗せたときの予告を強める（文字の説明は戻さない）。
4. **描画が重い**（屈折の描画先とスクリーン） → P2 と P3 で計測する。予算を超えたら、描画先の解像度と波長数を下げる。
5. **双子で諦める機能**（選択、翻訳、検索、拡大） → §6 の入口の動作を、読み上げソフトとキーボードで確認する。
6. **計算時間とデータ量**（12波長で計算時間が約4倍） → P1 で1形状の時間を測り、全体を見積もる。

## 13. やらないこと

- ハンバーガー、ナビバー、リンク列、パンくず、閉じるボタン、カード、モーダル、ドロワー
- 市販のモニター風の筐体、CRT、走査線、グリッチ、ネオン、パーティクル
- キーを画面外へ一斉に散らす演出、キーボードが割れて開く演出
- 単語をキーに刻印すること（ロゴキーを除く）
- カメラの自由な回転
